# z3-og — F* verified layer

Machine-checked F* modules for the z3-og stack, plus the KreMLin
extraction of the Low* helper to C99.

**Zero-sorry rule (owner's standing order):** no `admit`, no `sorry`,
no `assume`, and no vacuous lemma presented as a proof, anywhere in
this layer. Enforced mechanically — see "Zero-sorry check" below.

## Modules

| File | What it is |
|---|---|
| `SMT.RewriteProof.fst` | Owner-supplied, **byte-verbatim**. Boolean XOR, a small expression AST with an evaluator, and `xor_false_sound`: rewriting `e ^ false` to `e` preserves semantics under every environment. The proof is by structural induction and is fully discharged. |
| `SMT.LowExtract.fst` | Owner-supplied, **byte-verbatim**. Low* flat node record (`op`/`left`/`right` as `u32`) and `is_xor_false_identity`. Verified, then extracted to C — see `extracted/`. |
| `EGraph.Sovereign.fst` | Rebuilt from the owner's sketch of the same name (sketch kept in `docs/reference-sketches/`). The sketch's union returned its input unchanged and its soundness lemma stated the trivial proposition; neither is carried over. This version keeps the sketch's type shapes (`op`, `enode`, `eclass`, `egraph_state`), adds an explicit representative lookup `repr_of`, and implements `verified_union` as a real canonical-representative merge over the class list. Proved, with no placeholders: `union_merges` (after a union of two present classes, both representatives equal the first class's former representative) and `union_nodes` (merging never touches the node store), via two list-induction helper lemmas about the lookup/rewrite pair. The sketch's rewrite-soundness lemma is deliberately absent: over a real denotational semantics for `op` it is genuine future work, and it is recorded as such in the file header instead of being faked. |
| `compat/FStar.Buffer.fst` | Compatibility shim — see "Why a compat shim" below. Provides no buffer functionality. |
| `extracted/Custard.c`, `extracted/Custard.h` | C99 generated by KaRaMeL from `SMT.LowExtract.fst`. Generated code, left exactly as generated. |

## Extract `SMT.LowExtract` to C

This F* build's extraction engine is the whole-program "Custard"
compiler: there is no classic per-module OCaml extraction, so the
owner's classic pipeline (F* → `SMT_LowExtract.ml` → `krml`) is
realised as F* → `Custard.krml` → `krml`, with the owner's krml
flags (`-bundle`, `-no-prefix SMT.LowExtract`, `-drop FStar.UInt32`,
`-ccopts "-O3 -march=native -std=c99"`) preserved as far as this
toolchain accepts them. Deviations, all forced by the toolchain:

- This `krml` rejects `-bundle SMT.LowExtract=SMT.*` ("one of these
  modules doesn't exist: SMT.LowExtract"); `-bundle 'SMT.*'` is used.
- This `krml`'s own `.fst`-driving mode is broken against this F*
  build (it invokes `fstar.exe --codegen krml`, which F* rejects:
  valid targets are `OCaml|FSharp|KrmlC|KrmlRust|C|Cherry|Plugin`),
  so `krml` is run on the extracted `.krml` file instead.
- `-drop` draws a deprecation warning from this `krml` (Warning 10);
  it is still honoured.
- `-skip-compilation -skip-makefiles` are added so `krml` stops
  after C generation; the C compile check below is the documented
  compile step. (With the owner's `-skip-linking` instead, this
  `krml`'s internal compile step fails — its Warning 3, "external
  command failed" — after the C files have been written.)

```sh
# 1. Produce .checked files for the shim and the module
#    (this build writes them only under --cache_checked_modules,
#     and Custard extraction loads checked modules with fly_deps off)
fstar.exe --ext fly_deps=off --cache_checked_modules compat/FStar.Buffer.fst
fstar.exe --ext fly_deps=off --cache_checked_modules --include compat SMT.LowExtract.fst

# 2. Extract the module (as a library) to KaRaMeL's AST
mkdir -p /tmp/z3og-krml
fstar.exe --ext fly_deps=off --codegen KrmlC \
  --custard_entry_module SMT.LowExtract \
  --include compat --odir /tmp/z3og-krml SMT.LowExtract.fst

# 3. KaRaMeL to C99 (output lands in extracted/)
krml -tmpdir extracted -bundle 'SMT.*' -no-prefix SMT.LowExtract \
  -drop FStar.UInt32 -ccopts "-O3 -march=native -std=c99" \
  -skip-compilation -skip-makefiles /tmp/z3og-krml/Custard.krml

# 4. Compile check (the -D_DEFAULT_SOURCE define and the second
#    include path are for KaRaMeL's own krmllib headers, following
#    KaRaMeL's own Makefile.basic; the generated code is warning-free)
gcc -std=c99 -Wall -Wextra -D_DEFAULT_SOURCE \
  -I $FSTAR_HOME/include/krml -I $FSTAR_HOME/lib/krml/dist/generic \
  -c extracted/Custard.c -o /tmp/z3og-krml/Custard.o
```

Steps 1–2 also leave `SMT.LowExtract.fst.checked` and
`compat/FStar.Buffer.fst.checked` in the tree; those are build
artifacts and are not part of the delivered source.

### How the extracted C compares to the owner's supplied sample

The owner's sample (classic KreMLin output) declares
`SMT_LowExtract_flat_node` and
`SMT_LowExtract_is_xor_false_identity(node)` returning
`(node.op == (uint32_t)2U) && (node.right == (uint32_t)0U)`.
This toolchain's output (`extracted/Custard.c`) is:

```c
bool is_xor_false_identity(flat_node node)
{
  return node.op == 2U && node.right == 0U;
}
```

Same predicate, same struct fields (`uint32_t op/left/right`) —
semantically identical. The differences are naming and cosmetics:
because `-no-prefix SMT.LowExtract` takes effect in this `krml`,
identifiers are unprefixed (`flat_node`, `is_xor_false_identity`);
the files are named `Custard.c/.h` after the Custard program unit
rather than after the module; the redundant `(uint32_t)` casts are
not emitted; and the struct typedef lives in the header, not the
`.c` file.

The extracted object was also exercised with a 4-case harness
(xor-node with right child 0 → true; xor-node with right child 1 →
false; const node → false; var node with right child 0 → false):
**4/4 pass**.

## Why a compat shim

`SMT.LowExtract.fst` is owner-supplied and stays byte-verbatim, but
it was written against an older F*: it opens `FStar.Buffer` and
annotates fields with the bare type name `u32`. In this toolchain
neither name exists — `FStar.Buffer` (renamed `LowStar.Buffer` by
KaRaMeL in 2019) is not shipped anywhere in the distribution, and
`u32` is now spelled `FStar.UInt32.t`. The module uses nothing from
`FStar.Buffer` (no buffer types, no buffer operations), so
`compat/FStar.Buffer.fst` restores exactly the two missing names —
the namespace, and `u32` as a transparent alias for
`FStar.UInt32.t` — and nothing else. Any future module that actually
needs buffers will fail to resolve them against this shim rather
than silently linking against a fake.
